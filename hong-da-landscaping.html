Web Admin + Mobile App · Landscaping & Tender Management

One operations backbone, two interfaces.

Hong Da Landscaping runs plant supply and tendering for construction projects across Hong Kong. I designed a web admin covering the full back office, plus a companion mobile app for field workers to log tender progress on site — one shared design system, two purpose-built experiences.

Project Overview

A back office for the office, a camera-first app for the site.

Hong Da's team splits across two very different contexts: office staff managing clients, warehouses, products, and tender proposals at a desk, and field workers documenting planting progress on active construction sites. I designed one admin system for the former and a lightweight companion app for the latter — sharing the same brand and data model, built for how each group actually works.

Problem Office and field work needed one shared source of truth — but a dense admin table isn't usable one-handed on a job site, and a camera-first app can't hold 20+ back-office modules.
Goal Give each context its own interface — full-featured web admin, minimal mobile capture — on one brand and one design system.

Key UX Decisions

Three calls that shaped the product.

01

A dedicated app, not a responsive web view

ConsideredOne responsive web app for office and field
ShippedA separate mobile app with native capture patterns

Field work is camera-first and one-handed — a shrunk admin table doesn't fit that. A native action sheet and tag picker do.

02

Bilingual fields on every record

ConsideredEnglish-only interface with translation added later
ShippedEnglish / 繁體中文 tabs built into every form from day one

Hong Da's staff and clients work in both languages daily — bilingual couldn't be a bolt-on.

03

Permission matrix over fixed roles

ConsideredTwo or three fixed roles, e.g. Admin / Staff
ShippedPer-controller View / Add / Edit / Delete permissions

Tender and pricing data need finer control than a blanket role as the admin team grows.

Results & Reflection

What shipped.

0 Web admin modules, one shared system
0 Platforms shipped from one design system
0 Tender proposal states, draft to awarded
0 Photos per field upload, tagged on the spot

The real design problem here wasn't any single screen — it was resisting a one-size-fits-all interface for two very different users. Giving office staff full-featured tables and field workers a three-tap capture flow, from one shared system, is still the trade-off I'd make again first.
