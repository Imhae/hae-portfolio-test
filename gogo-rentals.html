Project Overview

One platform for quoting, renting, delivering, and billing.

GoGo Rentals runs a fleet of construction lifts — Genie scissor lifts and boom lifts — rented to contractors across Hong Kong. Before this platform, quoting, contracts, delivery, and billing were split across spreadsheets and paper forms handled separately by sales, operations, and finance. I designed an admin system that connects the entire rental lifecycle — quotation, rental note, auto-generated invoice, delivery note, payment, and revenue reporting — alongside equipment and parts inventory, usage reporting, and user management.

Problem & Goals

A rental business quietly running on spreadsheets.

Problem
  • Quoting, contracts, delivery, and billing lived in separate spreadsheets and paper forms across sales, operations, and finance.
  • Staff re-typed the same client and equipment details on every quotation, rental note, and invoice.
  • No shared view of which machines were idle, currently rented, or due for maintenance.
  • Outstanding balances and partial payments were tracked by hand, with no consolidated view of cash flow.
Goals
  • One connected platform covering the full quote-to-cash lifecycle.
  • Auto-generate invoices directly from rental notes to remove duplicate entry.
  • Give every machine a status — idle, in use, or due for maintenance — visible at a glance.
  • Make revenue, outstanding invoices, and settlement status visible on a single dashboard.

Key UX Decisions

Three calls that shaped the product.

01

One template, 14 modules

ConsideredA fully custom layout per module
ShippedOne shared list → detail → create/edit scaffolding

Staff use this system for minutes at a time between other jobs. Consistency across modules beats per-module optimization when the goal is a short learning curve.

02

Blue for actions, yellow for the logo

ConsideredExtend the brand's yellow into buttons and accents
ShippedA neutral blue action color; yellow stays in the logo

Yellow reads as a warning at this data density and has poor contrast as an action color. A calmer neutral system keeps status colors legible without competing.

03

Auto-generate invoices, and say so

ConsideredKeep invoice creation a fully separate manual step
ShippedInvoices generate automatically, with the rule stated on-screen

Automation removes duplicate entry, but only if staff trust it. Stating the rule directly on the Create Rental Notes screen keeps the system legible, not magic.

Challenges

What I'd revisit next.

! A single search box doesn't scale with record count

Every list — Clients, Products, Parts, Users — relies on one free-text search field. As records grow past a few hundred, status and date filtering will matter more than search alone. This is the top item on my list for the next iteration.

! The row menu can overlap the row below it

In dense tables, the kebab menu's dropdown sometimes sits over the next row's data. It's a small thing, but worth fixing before the record count grows further and the overlap gets more disruptive.

! Access levels are implied, not designed

The Users module shows an "Admin" badge but no second role exists yet. Before rolling access out beyond a single admin team, I'd want to define what a non-admin view actually restricts.

Reflection

The hardest part of this project wasn't any single screen — it was resisting the urge to design 14 bespoke modules instead of one adaptable system. Reusing a shared list → detail → create/edit template across departments as different as sales, operations, and finance meant real trade-offs: some modules could have been more specialized. In hindsight, I'd push earlier for basic list filtering and a defined second user role — both will matter more as the system scales past its first team of users. Choosing one shared design system over per-module polish is still the decision I'd make again first.
